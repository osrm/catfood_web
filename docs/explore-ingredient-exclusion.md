# 일반 탐색: 피하고 싶은 원료

일반 탐색(EXPLORE)의 추가 조건에서 고른 원료가 공개 검토 자료에 확인된 제품을 제외한다. 제품에 원료가 없거나 알레르기에 안전하다고 판정하는 기능이 아니다.

- 지원 항목은 `src/search.ts`의 `INGREDIENT_AVOID_OPTIONS`에 있는 23개 동물 유래 원료다. 모든 원재료·원료 계열을 지원하는 사전이 아니다.
- 레시피 이름과 원료 근거를 구분한다. generic fish/poultry, 불명확한 향미 표현을 특정 종으로 추정하지 않는다.
- 기존 catalog의 `confirmed_present_ingredient_terms` 중 선택한 항목이 하나라도 있으면 제외한다. 기존 SWITCH처럼 direct/flavor를 포함하는 확인 집합을 사용한다.
- 남은 제품에서는 `reviewed_not_found_ingredient_terms`의 미발견과 그 외 근거 부족을 별도 표시한다. 목록에 없다는 사실을 원료 부재로 변환하지 않는다.
- 원료 제외 상태를 positive match 개수나 품질·안전 점수에 넣지 않는다. 기존 형태·연령 및 positive 정렬과 recipe refine OR는 유지한다.
- 현재 catalog 배열만 사용한다. 조건 선택마다 API 요청을 추가하거나 원재료 전문·영양 데이터를 전수 선조회하지 않는다.

## 상태와 비교

일반 탐색 URL은 `avoidIngredients=chicken,duck`처럼 검토된 term만 저장하며 중복·지원하지 않는 값은 제거한다. SWITCH URL과 session의 기존 원료 회피 설정은 별도다.

조건 편집 draft는 적용 전까지 마지막 적용 조건을 바꾸지 않는다. 같은 원료 집합을 재적용하면 비교 목록을 유지하며, 원료 선택 순서는 조건 변경으로 취급하지 않는다. 실제 조건을 바꾸어 적용하면 기존 비교 초기화 정책을 따른다.

EXPLORE↔LOOKUP, 상세 왕복, 뒤로/앞으로와 새로고침에서 마지막 적용 조건과 비교 맥락을 유지한다. Home에서 새 일반 탐색을 시작하면 이전 조건은 지운다.

LOOKUP에서 수동으로 추가한 제품에 피하려는 원료가 확인되어도 비교 목록에서 자동 삭제하지 않는다. 비교 화면에 “피하려는 원료 확인”, 미발견, 미확인을 각각 표시한다.

기존 값·단위·제품/SKU/Formula 의미와 최대 5제품 비교·기존 SWITCH 판단은 바꾸지 않는다.

## 원료표의 세부 종류 표기 (제품 상세·비교)

원료 회피의 23종 판정과 **별개로**, 제품 상세·비교 화면은 선택된 원료표 원문에서 `어유`, `생선추출물`, `천연향료` 같은 포괄적인 표현을 찾아 원문 그대로 보여준다. 소비자는 원료 정보의 표기 수준을 비교할 수 있지만 CATFOOD는 제조사의 품질·성실도 점수를 매기지 않는다.

- 전체 목록(`full`)과 일부/요약 목록의 구분을 유지한다. 일부 목록에서 포괄 표현을 발견하지 못했다고 전체 원료가 구체적으로 공개되었다고 하지 않는다.
- 읽기용 대표 원료표만 검사한다. 다른 지역·배합의 보조 전체 목록을 합쳐 원료 종별 존재나 부재를 추론하지 않는다.
- 제품 빠른 보기에서는 기존 원료 조회 결과를 재사용해 원료 표기 수준과 한국 자료/동일 배합/대응 미확인 범위를 함께 표시한다. 별도 조회를 추가하거나 목록 카드마다 원료 전문을 가져오지 않는다.
- 원문에 세부 어종이 기재된 `어유(정어리, 멸치)`는 세부 어종 미기재 사례로 표시하지 않는다. 반대로 `어유`만 적혀 있다면 연어를 포함하거나 포함하지 않는다고 추정하지 않는다.
- 인식하는 주요 포괄 표현을 찾지 못했다는 사실은 **모든 원료의 완전 공개**나 **알레르기 안전성**의 증거가 아니다. API의 `confirmed_present`, `not_found_in_reviewed_evidence`, `insufficient_evidence` 결과는 바꾸지 않는다.
- 국내 제품과 자료 간 시장·포장·Formula 대응은 기존 원료 상세의 자료 범위 표기를 함께 읽어야 한다. 검색 결과 목록의 원료 제외 기준이나 정렬, DB의 미확인 제품 수는 변경하지 않는다.

### 원료표 확보와 세부 표기 구분

빠른 보기와 상세 원재료에서는 `전체 원료표 확인 / 일부 원료표만 확보 / 전체 목록 여부 미확인 / 원문 미확보`를 세부 종류 표기와 별도로 표시한다. 일부 목록에 `어유`가 있으면 **일부 원료표만 확보**와 **세부 어종 미기재**가 함께 보인다. 전체 목록을 확보했다는 사실도 모든 원료의 세부 종류가 밝혀졌다는 뜻으로 바꾸지 않는다.

비교 요약도 목록 확보 범위와 `원문 표현 — 세부 어종/동물 종류/향료 구성 미기재`를 함께 읽을 수 있다. 다른 원료에 특정 종이 등장해도 별도의 포괄 원료를 구체화하지 않으며, `정어리 또는 멸치`, `기타 어류`처럼 구성 범위가 미확정인 표현을 확정 표기로 처리하지 않는다. 제조사가 정보를 숨긴다는 평가나 완전 공개 판정은 하지 않는다. 기존 원료 회피 결과와 공개 API는 이 읽기 도움말과 별개다.

`동물성 단백질원: 닭고기`처럼 원료 분류 제목 뒤에 종류가 명시된 문구도 기재된 범위대로 읽는다. 전체 목록 확보 여부와는 별개이며, 같은 문구에 포괄적인 생선 원료가 함께 있으면 그 어종 미확인은 유지한다.

### 브라우저 검증

- `qa/ingredient-disclosure-review.mjs`: 예시 응답으로 전체/일부 목록, 포괄/구체 표기를 390/820/1440px에서 검증한다. 기존 fixture workflow에서 실행한다.
- `qa/ingredient-disclosure-live-review.mjs`: 실제 공개 API를 사용하는 빌드 또는 배포 주소를 대상으로 로얄캐닌·알레바·펠린내추럴·이나바의 상세, 빠른 보기, 비교를 390/1440px에서 확인한다. `CANDIDATE_URL`, `CANDIDATE_SHA`, `OUT_DIR`, `CHROME_PATH`를 지정할 수 있다. Playwright 드라이버는 기존 QA와 같은 방식으로 준비한다. 원료 응답과 화면 증거는 지정 출력 폴더에 보관한다.
- 두 검증은 첫 탐색 전부터 쓰기·분석 요청을 차단한다. 실제 공개 데이터 QA도 사람의 이해도 검증이나 전체 제품에 대한 정확성 보증을 의미하지 않는다.
