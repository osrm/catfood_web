# 후보를 보며 조건 정하기

현재 사료와 포장을 고른 뒤 바꿀 조건이 아직 없더라도 `후보부터 보기`로 진행할 수 있다. 메모를 해석하거나 브랜드·형태·특징을 자동 선택하지 않는다. 사용자가 고른 KEEP은 보존한다.

## 의미와 상태

- `criteriaUndecided=true`: 바꿀 조건을 후보를 보며 정하는 명시적 탐색이다.
- `noChangeIntent=true`: 사용자가 별도로 ‘특별히 바꾸고 싶은 점 없음’을 선택했다.
- 둘 다 false: 아직 미선택이거나 구체적인 조건을 편집 중이다. 구체적인 변경을 적용하면 미정 상태를 끝낸다.
- 미정 상태는 후보의 자격·평가·순서를 바꾸지 않는다. 기본 조건과 미확인 처리의 기존 계약을 따른다.
- 기존 version1 session은 새 필드를 false로 읽고, false일 때 기존 selection key를 그대로 유지한다. 미정의 true marker만 key에 추가한다. history/reload/상세·비교 왕복과 명시적 재시작 정책을 따른다.

## 차이 확인

미정 탐색의 빠른 보기에서 `열량·영양 비교` 또는 `원재료 비교`를 직접 고를 수 있다. 현재 사료를 기준으로 해당 탭을 열며, 선택한 후보를 비교 목록에 최대5개까지 담는 기존 동작을 재사용한다. 전체 후보의 영양·원재료를 선조회하지 않는다. 제품 상세로도 이동할 수 있다.

가격과 실제 먹는 반응을 비교한다고 약속하지 않는다. 해당 설명은 이 흐름의 접힌 도움말에서 확인할 수 있다. 표시값·한정자·포장 예외·원료 미확인/자료 미발견을 다른 뜻으로 바꾸지 않는다.

## 로컬 기록과 수집 경계

기존 intake 계약에는 조건 미정의 의미가 없다. 따라서 미정 탐색의 run/consideration/명시 기록은 전송하지 않고, 로컬 기록 context에만 미정 상태를 보존한다. 이후 구체적 조건을 적용하더라도 과거 미정 중 행동을 새 run으로 소급 전송하지 않는다. 이전의 별도 구체적 조건 기록은 원래 context와 수정/제거 의미를 유지한다.

메모는 계속 탭에만 보관하며 검색 조건·URL·원격 payload로 보내지 않는다. 기본 수집 flag는 false이며 이 기능이 서버 배포·수집 활성화를 허가하지 않는다.
