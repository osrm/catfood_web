# Comparison highlights

The comparison screen first summarizes differences before its full tables. This is a reading aid for the user's selected products, without ranking products or adding suitability scores.

- Overview puts selected condition outcomes first, groups confirmed shared conditions, and compares catalog facts with the current food (SWITCH) or first displayed product (general comparison). Missing values are labeled as differences in available information. Two missing values never establish a shared product fact. Additional differences remain available in a disclosure.
- Overview's full comparison record is explicitly expandable; summary actions and mobile pair/candidate controls remain available before expansion. Single-product general comparison retains the full record.
- Nutrition uses its primary comparison without a second summary. Numeric energy differences require known identical supported feed types, positive finite energy, and an applicable source for each energy field. Supplemental energy follows its own scope, market, and formula applicability. Unknown, foreign unresolved, loading, or failed sources cannot produce a numeric difference. Evidence package labels retain their own variant identity; a selected 1 kg package does not relabel a 3 kg observation.
- Ingredients uses its primary pair/table rather than repeating a summary. Each selected source keeps list completeness, actual wording examples and applicability. An oil explicitly naming herring and an unspecified fish oil remain distinguishable. Supplemental full lists and recipe metadata cannot fill in an unnamed species in the selected source. No ingredient-absence or product-quality conclusion follows from these examples.

Desktop summarizes all comparison candidates. Mobile follows the displayed pair or selected SWITCH candidate, including pair changes and removals. The comparison reference is always named. Overview starts no additional nutrition or ingredient reads; the summary reuses existing tab data and error/retry behavior.

Validation includes scope/unknown/priority tests, mobile selection/removal integration tests, and real public-data journeys at mobile and desktop widths. Automated review is not human user validation.
